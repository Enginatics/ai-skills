# Blitz Report Excel Add-in Skills

## Analytics

- `br-anomaly-detection`: Find unusual or suspicious rows in a Blitz Report dataset — outlier transactions, duplicate invoices, abnormal amounts, data-quality errors — using robust statistics, Mahalanobis distance, Benford's Law, and duplicate detection. Use this whenever the user wants to detect anomalies, outliers, exceptions, "things that look wrong", duplicate or suspicious invoices, fraud signals, or data-quality issues in an Oracle EBS / Blitz Report sheet. Trigger it for "flag anything unusual", "find outliers", "check for duplicates", or "what looks suspicious here", even without a named method.
- `br-clustering`: Segment a Blitz Report dataset into natural groups using K-Means or DBSCAN, then profile and name each segment in plain business language. Use this whenever the user wants to cluster, segment, or group rows of an Oracle EBS / Blitz Report sheet — e.g. "segment our customers", "group these vendors by spend behaviour", "find natural clusters in this data", "which items behave alike", or any request to discover groupings the data isn't already labelled with. Trigger it even when the user says "segment" or "group" without naming an algorithm.
- `br-data-dashboard`: Build an interactive dashboard on top of any tabular data sheet — KPI cards, charts, and slicers — without modifying the source columns. Use when the user asks for a dashboard, demo view, or interactive summary built from an existing data table or pivot.
- `br-forecasting`: Forecast a time series from a Blitz Report — future demand, sales, GL trend, AR collections, cash, or inventory — using Excel's native FORECAST.ETS (Holt-Winters) with seasonality detection, confidence intervals, and a backtest accuracy check. Use this whenever the user wants to forecast, project, predict, or extrapolate future values of a dated metric in an Oracle EBS / Blitz Report sheet — "forecast next quarter's sales", "project AR collections", "what will the GL trend look like", "predict demand". Trigger it for any "forecast / projection / what will happen next" request over time.
- `br-rfm-analysis`: Score customers (or vendors) on Recency, Frequency, and Monetary value from a transactional Blitz Report and map them to named segments like Champions, Loyal, At Risk, and Hibernating. Use this whenever the user wants RFM analysis, customer-value segmentation, to find their best / lapsing / at-risk customers, prioritise accounts, or target win-back and retention from an Oracle EBS / Blitz Report of invoices, orders, or sales. Trigger for "who are our best customers", "which customers are slipping away", "segment customers by value", or any RFM request.

## Audit and Security

- `br-audit-trail`: Answer "who changed what, when" across Oracle EBS setups and access: mine the FND Audit Trail reports for setup and profile changes by record and column, correlate with user login history and responsibility assignments, and produce a reviewable change narrative for an audit window or an incident. Read-only. Use when the user asks who changed a setup, wants a segregation-of-duties or access review, needs audit evidence for a period, or is investigating an unexpected configuration change.
- `br-instance-diff`: Compare Oracle EBS instances through Blitz Reports in Excel: run the same report with the same parameters against two configured environments (DEV/TEST/PROD, pre/post-upgrade, source/clone) and explain the differences — row counts, missing and extra keys, changed values by column — or diff the two instances' report catalogs. Use when the user asks to compare environments, validate an upgrade or clone, check TEST against PROD, or "why is this report different on X".

## Cash Management

- `br-ce-recon-readiness`: Assess Oracle EBS Cash Management bank reconciliation / period-close readiness in Excel: have the br-run-reports skill extract unreconciled bank statement lines and the GL cash reconciliation, then give a red/amber/green verdict with remediation and build a CE reconciliation-readiness scorecard. Use when the user asks about bank reconciliation status, unreconciled statements, or cash management period close.

## Cash and Working Capital

- `br-cash-working-capital`: Orchestrate a full Oracle EBS cash & working-capital review in Excel: run the duplicate-payment recovery, AR collections worklist, and AP payment-run optimizer, cross-check the open duplicate invoices against the recommended pay-run (so you don't pay a duplicate you're about to claw back), then assemble one master scorecard with the total cash opportunity by lever (recover / protect / capture discounts / collect / DPO headroom), a combined net-cash-by-week view, and the ranked cross-lever action list. Use when the user asks for a working-capital review, "where's our cash", free up / find cash, a cash opportunities pack, or a combined AP/AR cash position.

## Fixed Assets

- `br-fa-close-readiness`: Assess Oracle EBS Fixed Assets period-close readiness in Excel: have the br-run-reports skill extract the mass-additions backlog, depreciation/reserve status, and FA-to-GL reconciliation, then give a red/amber/green verdict with remediation and build an FA close-readiness scorecard. Use when the user asks "can we close FA for {period}", "fixed assets period close readiness", mass additions backlog, or depreciation not run.

## General Ledger

- `br-fsg-conversion-review`: Finish a financial statement workbook converted from Spreadsheet Server or GL Wand to Blitz FSG: read its Conversion Log sheet, fix in the workbook what the converter could not (period cells read by other formulas, formula-driven format and segment cells, hierarchy suffixes, unsupported currency types, cells left unconverted), ask the user about the rest, and mark every log line. Use when the user asks to review, finish, fix or check a converted Spreadsheet Server or GL Wand workbook, its conversion log, or "the warnings from the conversion". Edits the workbook only; never writes to Oracle EBS.
- `br-gl-account-coder` (writes to EBS): Suggest GL account coding from the ledger's own history: given transactions to code (or re-code), mine GL Account Analysis for how this entity has historically coded the same supplier, source, category or description, and propose the account combination with a confidence level and the precedent shown. Optionally stage approved corrections as a journal via the GL Journal Upload — only on explicit user confirmation. Use when the user asks "which account should this go to", wants miscoding candidates found, or needs a reclass journal drafted. Recommend-first; WRITES to Oracle EBS only via the gated journal step.
- `br-gl-close-readiness`: Assess Oracle EBS General Ledger period-close readiness in Excel: have the br-run-reports skill extract GL period statuses, unposted/error journals, and the trial balance, then give a red/amber/green verdict with remediation and build a GL close-readiness scorecard. Use when the user asks "can we close GL for {period}", "GL period close readiness", unposted journals, subledgers not closed, or out-of-balance.

## Getting Started

- `br-analytics-standards`: Shared performance and coding standards for all br_ analytics skills (br-ap-holds-analysis, br-ap-close-readiness, br-ar-close-readiness, br-gl-close-readiness, br-fa-close-readiness, br-inv-cost-close-readiness, br-ce-recon-readiness, br-subledger-gl-reconciliation, br-close-process-monitor, br-month-end-readiness). Read at the start of any br_ skill run via read_skill("br-analytics-standards").
- `br-report-finder`: Find the right Oracle EBS Blitz Report by MEANING, not by name: load the full report library once into the workbook, then match the user's business question ("which report shows unapplied receipts by operating unit?") against every report's name, category and description, explain the top candidates, and hand the chosen one to br-run-reports. Use when the user doesn't know a report's name, asks "is there a report that...", "which report shows...", or a name search found nothing.
- `br-run-reports`: Find, run, and analyze Oracle EBS Blitz Reports in Excel (GL, AP, AR, INV, PO, WIP, FA, HR and concurrent-program data). Use when the user wants to run or analyze an Oracle/EBS report.
- `br-run-uploads` (writes to EBS): Create, load or update Oracle EBS records from Excel with Blitz Uploads via the BLITZ REPORT ADD-IN (the br_* worksheet functions) - journals, invoices, purchase documents, items, suppliers, customers, assets and more (GL, AP, AR, PO, INV, WIP, HR, FA, CE). Use whenever the user says they want to UPLOAD, LOAD, POST, ENTER, CREATE or UPDATE any EBS data or document ("upload a journal entry", "upload journals", "load invoices", "create a PO", "post a journal"). In this add-in "upload" means sending data INTO Oracle EBS - it does NOT mean the user is attaching a file to the chat, so never ask them to attach one and never hand-build a mock table in the sheet instead. NOT for the standalone Blitz Upload template file (UploadTemplate.xlsm with bu_* functions) - that is bu-fill-upload's territory. This WRITES to Oracle EBS.

## Inventory

- `br-inv-cost-close-readiness`: Assess Oracle EBS Inventory/Costing period-close readiness in Excel: have the br-run-reports skill extract pending inventory transactions, missing WIP/receiving accounting, and pending cost adjustments, then give a red/amber/green verdict with remediation and build an Inventory close-readiness scorecard. Use when the user asks "can we close inventory for {period}", "inventory/costing period close readiness", pending/uncosted transactions, stuck MTL interfaces, or missing accounting.
- `br-inv-cycle-count-planner`: Plan and steer Oracle EBS cycle counting: analyse count accuracy history, find never-counted and overdue items, recommend count priorities by value/velocity/accuracy (ABC-weighted), and surface the approval and adjustment backlog. Read-only — recommendations feed the customer's own cycle count scheduling in EBS. Use when the user asks what to count next, why inventory accuracy is slipping, which adjustments await approval, or wants a count program review.
- `br-inv-exception-triage`: Triage Oracle EBS Inventory exceptions in Excel: have the br-run-reports skill extract negative on-hand balances, stuck interface/error transactions, and cycle counts pending approval, then rank everything by severity with a recommended owner and fix, and build one exception dashboard. Use when the user asks what's wrong in inventory, negative on-hand, stuck transactions, unprocessed material transactions, or an inventory exception review.
- `br-inv-stock-optimizer` (writes to EBS): Recommend min/max quantities, reorder points and safety stock per item and subinventory in Oracle EBS from actual demand history and on-hand position — then, only on explicit user confirmation, apply the approved recommendations back to EBS via the INV Item Subinventory Upload or INV Safety Stock Upload. Use when the user asks to optimize stock levels, review min/max settings, right-size safety stock, reduce excess inventory, or fix reorder points. WRITES to Oracle EBS (optional, gated).

## Manufacturing

- `br-bom-validator` (writes to EBS): Validate Oracle EBS bill-of-material accuracy against how the shop floor actually consumes material: compare BOM structures with WIP component requirements and shortages, flag suspect components (never issued, always short, quantity drift), and stage approved BOM corrections via the BOM Bill of Materials Upload — only on explicit user confirmation. Use when the user asks whether BOMs are accurate, why jobs are always short the same part, or wants BOM cleanup done. Recommend-first; WRITES to Oracle EBS only via the gated correction step.
- `br-wip-variance-analysis`: Analyze Oracle EBS WIP job health and cost exposure in Excel: have the br-run-reports skill extract job statuses, WIP value, and component shortages, then rank stuck and past-due jobs, surface value concentration and close candidates, and build one WIP analysis dashboard. Use when the user asks about open WIP jobs, jobs past due, WIP value, discrete job aging, component shortages, or which jobs should be closed.

## Payables

- `br-ap-close-readiness`: Assess Oracle EBS Accounts Payable period-close readiness in Excel: have the br-run-reports skill extract "AP Period Close Exceptions", summarise the blockers by exception type, give a red/amber/green readiness verdict with the remediation for each blocker, and build an AP close-readiness scorecard. Use when the user asks "can we close AP for {period}", "AP period close readiness", "what's blocking the AP close", unaccounted invoices/payments, or untransferred AP accounting.
- `br-ap-duplicate-hold` (writes to EBS): Stop payment of suspected duplicate AP invoices from Excel: take the unpaid duplicates a br-ap-duplicate-payments run identified, place a payment-blocking hold on each suspect copy via the "AP Invoice Hold Upload", and record the duplicate evidence in the hold reason — only on the user's explicit confirmation. Use when the user asks to block the duplicates, hold the suspect invoices, stop the double payment, or action a duplicate-payments analysis. WRITES to Oracle EBS.
- `br-ap-duplicate-payments`: Find duplicate and overpaid Oracle EBS Accounts Payable invoices/payments in Excel: have the br-run-reports skill extract the AP invoice universe, fuzzy-match it for duplicate-entry patterns (same supplier + amount, re-keyed invoice numbers, transposed digits, duplicate vendor masters, cross-OU double entry), separate recoverable (both paid) from preventable (one still open), and build a ranked recovery worklist with $-at-risk. Use when the user asks to find duplicate payments, duplicate invoices, overpayments, recover overpaid cash, or an AP recovery audit.
- `br-ap-hold-release` (writes to EBS): Release Oracle EBS AP invoice holds from Excel: take the holds that qualify for release, pre-populate the "AP Invoice Hold Upload" grid with the correct release reason per hold, validate it, show the user exactly what will be released, and — only on their explicit confirmation — submit it so Payables releases the holds. Use when the user asks to release invoice holds, action a holds analysis, clear matching holds, unblock invoices for payment, or "release the ones we can". WRITES to Oracle EBS.
- `br-ap-holds-analysis`: Analyze Oracle EBS AP invoice holds in Excel: run the "AP Invoice on Hold" Blitz Report, categorise and age the holds, flag anomalies, build a holds dashboard, flag RELEASE CANDIDATES and offer to hand them to br-ap-hold-release for action. Use when the user asks for an AP holds analysis, an invoice-holds dashboard, "what's on hold", aged AP holds, holds by supplier / hold type, or to analyse and release holds.
- `br-ap-intelligence`: Build a live AP intelligence dashboard in Excel from Oracle EBS: run the "AP Cash Requirement" Blitz Report and lay out the five payables KPIs (invoices on hold, total AP outstanding, overdue 30+ days, approved due within 7 days, unapproved due within 15 days), a ranked AI action summary, an AI commentary per KPI, drill-down lists, due-bucket and supplier tables, and answer follow-up questions as new KPI cards. Use when the user asks for an AP dashboard, AP KPIs, the payables position, "what's outstanding / overdue / on hold / unapproved", an AI summary of accounts payable, or an AP intelligence view. Hands hold release, hold detail and pay-run planning to the specialist skills.
- `br-ap-invoice-upload`: Create Oracle EBS AP invoices from source documents using the BLITZ REPORT ADD-IN (the br_* worksheet functions) — supplier invoices, reimbursement vouchers, freight bills, utility statements, expense receipts — by reading the documents, running the AP Invoice Upload, filling its sheet, then validating against real EBS and self-correcting. Use when the user has invoices/bills/vouchers (PDF, image, Word, text, or typed out) and wants them entered into Oracle Payables via the Blitz Report add-in. NOT for the standalone Blitz Upload template file (UploadTemplate.xlsm with bu_* functions and a Parameters sheet) — that is the bu-ap-invoice-upload skill's territory.
- `br-ap-payment-actions` (writes to EBS): Act on a br-ap-payment-optimizer run from Excel: produce the prioritized pay-run list for the invoices to pay now (discount capture), and — on explicit confirmation — place payment-blocking holds via the "AP Invoice Hold Upload" on the invoices the user chooses to defer. Use when the user asks to action the payment optimization, defer the deferrable invoices, block payments we want to delay, or prepare the pay run. WRITES to Oracle EBS (defer-holds only).
- `br-ap-payment-optimizer`: Optimize an Oracle EBS Accounts Payable payment run in Excel: have the br-run-reports skill extract the AP cash requirement (due invoices, available early-pay discounts, due dates, payment priority), classify each invoice as capture-discount / pay-to-avoid-late / defer-to-due / priority-must-pay, select the best pay run within a cash constraint by discount ROI, quantify the discount $ captured and DPO impact, and build a payment-run dashboard. Use when the user asks which invoices to pay and when, capture early-pay discounts, optimize a payment batch, plan a cash disbursement, or improve DPO.

## Period Close

- `br-close-process-monitor`: Monitor the Oracle EBS concurrent programs that drive a period close in Excel: have the br-run-reports skill extract recent Create Accounting / Transfer to GL / Cost Manager / Depreciation / Journal Import / AutoInvoice request status, flag errored, stuck, and long-running close jobs, and build a close-process monitor dashboard. Use when the user asks whether the close programs are running/erroring, "CP manager status", or stuck concurrent requests.
- `br-month-end-readiness`: Orchestrate a full Oracle EBS month-end close readiness assessment in Excel: run the per-module readiness checks (AP, AR, Inventory/Costing, FA, GL), the close-process monitor, and the subledger-to-GL reconciliation, then assemble one master scorecard with a per-module red/amber/green status, the ranked blockers, and the recommended close sequence. Use when the user asks "are we ready to close {period}", "month-end readiness", or a full close status.
- `br-subledger-gl-reconciliation`: Reconcile Oracle EBS subledgers to the General Ledger in Excel: have the br-run-reports skill extract AP, AR, Inventory and FA control balances and tie each to its GL control account, surfacing the variance per subledger with a red/amber/green verdict. Use when the user asks to reconcile AP/AR/INV/FA to GL, subledger-to-GL tie-out, or control account differences at period end.

## Purchasing

Use when the user asks "can we close PO for {period}", "purchasing close readiness", "accrual reconciliation status", or uninvoiced receipts backlog.

Read-only. Use when the user asks about match holds, quantity/price mismatches, "why is this invoice on match hold", or wants the match-exception backlog worked down.
- `br-supplier-risk-scoring`: Score Oracle EBS suppliers on risk in Excel: have the br-run-reports skill extract spend, holds, price variance and delivery history, then combine dependency, reliability, price stability and anomaly signals into a ranked supplier risk register with a named driver per supplier. Use when the user asks which suppliers are risky, supplier risk review, vendor scorecard, supplier dependency/concentration, or who to review before contract renewal.

## Receivables

- `br-ar-close-readiness`: Assess Oracle EBS Accounts Receivable period-close readiness in Excel: have the br-run-reports skill extract unaccounted AR transactions, AutoInvoice interface errors, and the AR-to-GL reconciliation, then give a red/amber/green verdict with remediation and build an AR close-readiness scorecard. Use when the user asks "can we close AR for {period}", "AR period close readiness", unaccounted receivables, unapplied receipts, or AutoInvoice backlog.
- `br-ar-collections-notes` (writes to EBS): Log collection notes into Oracle EBS Advanced Collections from Excel: take the ranked customers and drafted dunning messages a br-ar-collections-worklist run produced, stage one note per customer via the "IEX Collection Note Upload", and — on the user's explicit confirmation — submit them so the collections team sees the worklist as logged activity. Use when the user asks to log the collection notes, post the worklist to Collections, record the dunning messages, or action a collections worklist. WRITES to Oracle EBS.
- `br-ar-collections-worklist`: Build a prioritized Oracle EBS Accounts Receivable collections worklist in Excel: have the br-run-reports skill extract open AR aging, past-due detail and disputes, score each customer by collectible-$-at-risk (aging severity), exclude disputed balances, assign a dunning tier, draft the reminder text per tier, and build a collections dashboard. Payment-behaviour (receipt-history RFM) re-ranking is an add-on that runs only when the user asks for it. Use when the user asks for a collections worklist, who to chase, dunning priorities, reduce DSO, overdue receivables to call, or AR collections prioritization.
- `br-ar-credit-risk`: Score customer credit risk and analyse DSO from Oracle EBS Receivables: combine credit limits and utilization, aging severity, payment behaviour and balance trend into a per-customer risk grade with the drivers named, plus a DSO decomposition showing which segments and behaviours move it. Read-only. Use when the user asks which customers are a credit risk, wants credit limits reviewed, asks "why is our DSO rising", or needs a credit-review worklist.
